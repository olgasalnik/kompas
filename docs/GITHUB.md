# Как выложить «Компас» на GitHub

Итог: код лежит в репозитории, а сайт сам публикуется по ссылке вида `https://<аккаунт>.github.io/<репозиторий>/`.
При каждом обновлении GitHub прогоняет 120 автотестов, собирает сайт и выкладывает новую версию. Делать это вручную
не нужно.

Понадобятся только аккаунт на [github.com](https://github.com) и 10–15 минут.

---

## Шаг 1. Загрузить код — через GitHub Desktop (рекомендую)

GitHub Desktop — бесплатная программа от GitHub: всё делается кнопками, без командной строки.

1. Скачайте и установите [GitHub Desktop](https://desktop.github.com/), войдите в свой аккаунт GitHub.
2. Распакуйте архив `Компас — исходный код для GitHub.zip` в удобное место, например `Документы\kompas`.
   (Или используйте папку проекта `kompas` как есть — лишнее исключится само.)
3. В GitHub Desktop: **File → Add local repository…** → выберите папку `kompas`.
   Программа скажет, что это ещё не репозиторий, — нажмите **create a repository** → **Create repository**.
4. Нажмите **Publish repository**. В окне:
   - **Name:** `kompas` (или своё имя — оно станет частью ссылки на сайт);
   - **снимите галочку «Keep this code private»** — бесплатный GitHub Pages работает только для публичных репозиториев.
     Все данные в проекте синтетические, публиковать их можно;
   - **Publish repository**.

Папки `node_modules`, `dist`, `offline` и модели распознавания в репозиторий не попадут — это задано в `.gitignore`.
GitHub соберёт всё сам.

### Запасной способ — через браузер

На странице репозитория: **Add file → Upload files** и перетащите файлы. Но GitHub в браузере принимает **не больше
100 файлов за раз**, а в проекте их около 190. Поэтому придётся загружать частями, следя, чтобы папки оказались на
своих местах, — GitHub Desktop заметно проще.

---

## Шаг 2. Включить публикацию сайта

1. Откройте репозиторий на github.com → **Settings** → слева **Pages**.
2. В разделе **Build and deployment → Source** выберите **GitHub Actions**.

## Шаг 3. Дождаться сборки и получить ссылку

1. Откройте вкладку **Actions**. Там будет запуск **Deploy to GitHub Pages**: жёлтый кружок — идёт сборка,
   зелёная галочка — готово (2–4 минуты).
2. Если запуск красный, а вы включили Pages уже после загрузки кода, откройте этот запуск и нажмите
   **Re-run all jobs**.
3. Ссылка на сайт — в **Settings → Pages** («Your site is live at …») или в самом запуске, в шаге **deploy**.
   Обычно это `https://<аккаунт>.github.io/kompas/`.
4. Вставьте ссылку в начало `README.md` вместо `https://<аккаунт>.github.io/<репозиторий>/` и в QR-код для
   презентации и постера.

---

## Шаг 4. Проверить, что всё работает

Откройте ссылку в **Chrome или Edge** (на телефоне — Chrome для Android, Safari для iPhone).

| Что проверить | Где | Что увидите |
|---|---|---|
| Хранение данных | Сделайте запись как пациент, перезагрузите страницу | Запись на месте. Данные хранятся зашифрованными в браузере |
| Загрузка фото | «Я пациент» → Профиль → «Мои документы» → «Прикрепить» | Фото с телефона уменьшится и прикрепится |
| Распознавание текста | «Я врач» → пациент → «Документы» → «Распознать текст» | Первый раз скачаются модели (≈13 МБ), дальше — 2–5 секунд |
| Голосовой ввод | Значок микрофона у полей ввода | Браузер спросит разрешение на микрофон — нажмите «Разрешить» |
| Голосовые сообщения | Чат с врачом → значок звуковой волны | Запись до 1 минуты, прослушивание и расшифровка |
| Пациент → врач | Две вкладки: «Я пациент» и «Я врач» | Сообщение пациента сразу появляется у врача |
| Защита данных | «Я врач» → «Защита данных» | «Зашифровано», и как данные выглядят на диске |

Что нужно знать:

- **Голосовой ввод** (речь → текст) работает в Chrome, Edge и Safari и требует интернета: речь распознаёт сервис
  браузера. В Firefox его нет — там можно печатать. Голосовые сообщения (запись звука) работают во всех современных
  браузерах.
- **Данные у каждого посетителя свои**: сервера нет, всё хранится в его браузере. Начать заново — кнопка «Демо» в
  правом нижнем углу → «Сброс стенда».
- **Микрофон** работает только по защищённой ссылке (`https://…github.io`) или на своём компьютере
  (`http://localhost`). По адресу вида `http://192.168.…` браузер микрофон не даст.

---

## Обновить сайт после изменений

В GitHub Desktop: внизу слева кратко опишите изменения → **Commit to main** → **Push origin**. Через 2–4 минуты
сайт обновится сам.

## Запустить у себя на компьютере

- **Windows:** установить [Node.js](https://nodejs.org/) (версия LTS) → двойной щелчок по `start-windows.bat`.
- **macOS / Linux:** установить Node.js → в терминале в папке проекта `sh start-mac-linux.sh`.

Первый запуск ставит зависимости (1–3 минуты), потом сайт сам откроется на `http://localhost:5180`. Окно с
командной строкой не закрывайте, пока пользуетесь сайтом.

## Если что-то не так

| Проблема | Что сделать |
|---|---|
| В Actions красный крестик на шаге **deploy** | Не включён Pages (Шаг 2). Включите и нажмите **Re-run all jobs** |
| Красный крестик на шаге **npm test** | Сломался автотест — откройте шаг, там написано, какой именно |
| Ссылка открывает «404» | Подождите 1–2 минуты после зелёной галочки и обновите страницу |
| Нет вкладки **Pages** или её нельзя включить | Репозиторий приватный — сделайте его публичным: Settings → General → Danger Zone → Change visibility |
| Не работает микрофон | Откройте в Chrome или Edge, разрешите микрофон (значок замка в адресной строке) |
| Пропали данные | Данные хранятся в конкретном браузере; в режиме «инкогнито» они исчезают при закрытии окна |
